Эхний схемд вэб болон PHP API-г тусад нь харуулсан. Хоёр дахь схемд хэрэглэгчийн вэб үйлдлийг GOStore сервертэй харилцах нэг сум болгон хураангуйлсан. SQLite хадгалалтыг серверийн үйлдэлд нэгтгэсэн; тусдаа үйлчилгээ гэж үзээгүй. Админы худалдан авах үйлдлийг серверээс OT / Taobao руу гарах хүсэлтээр үзүүлсэн.

Хөх, нил ягаан, хүрэн, оюу өнгө нь үе шатыг ялгана. Тасархай сум нь хариу эсвэл мэдэгдэл; ногоон бүдүүн сум нь биет барааны хөдөлгөөн. Банкны апп–QPay дотоод ажиллагаа, Хятадын тээвэрлэгч болон УБ хүргэлтийн ажилтныг тусдаа оролцогч болгон задлаагүй.

## Нөхцөлүүд

- Үндсэн урсгал: хэрэглэгчийн сагсны checkout, QPay төлбөр, Taobao худалдан авалт. Хуучин supplier хүсэлт болон түр зогссон бэлэн барааны худалдааг тусгаагүй.
- Taobao автомат худалдан авалт нь тусгай тохиргоотой, анхдагчаар унтраалттай. 1688 барааг гараар худалдаж авна. Гадаад худалдан авалтын timeout / 5xx үед админ шалгах шаардлагатай.
- Эхний төлбөр бараа, Хятад доторх хүргэлт, үйлчилгээг хамарна. Бодит хэмжилтээр карго болон сонгосон УБ хүргэлтийг эцсийн тооцоонд оруулж, өмнө төлснийг хасна.
- Эцсийн үлдэгдэл 0 бол хоёр дахь схемийн III үе шатыг алгасана. Анхны нэхэмжлэлийг өөрчлөхгүй.
- Callback дангаараа төлбөр батлахгүй. Сервер QPay `/v2/payment/check`-ийн хариуг шалгана. Вэбийн `payment-check` нь мөн серверийн шалгалтыг ажиллуулдаг.
- Авах кодыг зөвхөн `ready_pickup` эсвэл `out_for_delivery` төлөвт, эцсийн тооцоо батлагдсан, өр/буцаалтын зөрүүгүй, нээлттэй зөрчилгүй үед хэрэглэгчид харуулна. Менежер хэрэглэгчээс авсан кодыг серверт шалгуулна.
- Алдааны бүх салаа, давтан оролдлого, authentication/token шинэчлэлтийг сум бүрээр дэлгээгүй.
