# Эрээн агуулах: Хятад дахь хүргэлтийн дэлгэрэнгүй

Эрээн менежер → захиалгын дэлгэрэнгүй → **中国境内物流 · 发往二连**.
**刷新国内物流** товч нь захиалгын хадгалсан TaoWorld дэд дугааруудаар
дотоодын хүргэлтийг уншина. Худалдан авалт болон төлбөр үүсгэхгүй.

Харагдах мэдээлэл:

- Хятадын хүргэлтийн компани, лавлах утас, хуулах боломжтой tracking дугаар.
- Худалдан авалтын үндсэн/дэд дугаар болон Taobao захиалгын дугаар.
- Багц тус бүрийн төлөв, хамгийн сүүлийн хөдөлгөөн, бүх дамжлагын түүх:
  огноо, цаг, муж/хот/дүүрэг, салбар/дамжуулах төв, дараагийн буудал.
- Хүлээн авагчийн нэр, утас, хаяг, шуудангийн код.
- Багцад орсон барааны нэр, хувилбар, тоо.

Эх сурвалж нь TaoWorld-ийн албан ёсны
[`/logistics/detail/get`](https://open.taobao.global/doc/api.htm#/api?cid=16&path=/logistics/detail/get&methodType=GET/POST)
API; `purchase_order_line_id` параметрт захиалгын хадгалсан `sub_purchase_order_id`
очдог. API баримтын бүтцийг 2026-11-02-нд шалгаж, бодит захиалгад HTTP 200,
`success=true`, 1 багц / 4 хөдөлгөөн буцаж ирснийг баталсан.

## Хадгалалт ба эрх

2026-11-08-аас TaoWorld worker илгээгдсэн боловч агуулахад уншуулаагүй захиалгын дэлгэрэнгүйг
арын горимд шинэчилнэ (нэг удаад нэг захиалга, захиалга бүрийг 6 цагт нэг удаа). «已签收» гэсэн ч
бүртгэгдээгүй илгээмж «到货提醒» хэсэгт гарна ([erenhot-workflow.md](erenhot-workflow.md)).

Хуудас нээхэд нийлүүлэгч рүү хүсэлт хийхгүй. Амжилттай хариуг 10 минут,
амжилтгүй оролдлогыг 2 минутын давтамжаар хязгаарлана. Нэг шинэчлэлтэд
хамгийн удаан шинэчлэгдээгүй 3 хүртэл дэд захиалга асууна. Алдаа эсвэл
бүтэц дутуу хариу ирвэл өмнөх амжилттай мэдээллийг хадгалж, хуучин цаг
болон анхааруулгатай харуулна. Жагсаалтад бүх хөдөлгөөний мэдээлэл ачихгүй.

Нарийвчилсан мэдээлэл `purchase.domestic_tracking` дотор хадгалагдана.
Зөвхөн тухайн Эрээн агуулахын менежерт гарна; хэрэглэгчийн API `purchase`-ийг
устгаж, УБ менежерт зөвхөн өмнөх хязгаарлагдсан inbound төлөвийг өгнө.
Хүргэлтийн `签收` төлөв нь агуулах хүлээн авсны баталгаа биш; захиалгын
агуулахын төлөв, хүлээн авалтын түүхийг энэ API өөрчлөхгүй.
