# GOStore бүтэц, ажиллагааны шалгалт — 2026-10-30

Сайтын үндсэн хэрэглэгч, админ, агуулах, төлбөр, TaoWorld худалдан авалтын урсгалыг кодын болон тусгаарласан API/хөтчийн тестээр шалгав. Production дээр унших шалгалт хийж, илэрсэн засваруудыг байршуулсан. Энэ аудитын үеэр бодит захиалга, нэхэмжлэл, нийлүүлэгчийн төлбөр шинээр үүсгээгүй.

## Бүтэц

| Хэсэг | Үүрэг, эх код |
| --- | --- |
| Дэлгүүр | HTML/CSS/JavaScript; эх файлуудыг `scripts/bundle.cjs` нэгтгэнэ. `/`, `/v/{id}`, `/brands/{brand}`, `/cart`, `/help`, `/account` маршрутууд. |
| API ба өгөгдөл | `api/index.php`, `server/bootstrap.php`; session, CSRF, эрх, SQLite өгөгдөл. Нууц тохиргоо болон өгөгдөл нийтэд нээлттэй биш. |
| Каталог | `supplier.php` нийтлэг интерфейс, `taoworld-catalog.php` шууд хайлт, дэлгэрэнгүй, зурагт хайлт. OT нь тусдаа хуучин provider. |
| Checkout | `checkout.php`, `shipping.php`; сервер SKU, тоо, үнэ, үлдэгдэл, ханш, хүргэлтийг баталгаажуулна. Хэрэглэгчийн харсан дүн зөрвөл шинэ тооцоо шаарддаг. |
| Төлбөр | `qpay.php`, `freight-payment.php`; анхны болон эцсийн карго төлбөрийн тусдаа нэхэмжлэл, серверийн тулгалт. |
| Нийлүүлэгчийн худалдан авалт | `taoworld-auth.php`, `taoworld-http.php`, `taoworld-purchase.php`; хувийн токен, тогтвортой захиалгын дугаар, төсөв, төлөвийн тулгалт. `scripts/taoworld-worker.php` cron-оор ажиллана. |
| Хэрэглэгч | `customers.php`, `customer-state.php`; бүртгэл, өөрийн захиалга, хаяг, сагс/хадгалсан барааны синк. |
| Агуулах | `warehouse.php`, `warehouse-batches.php`, `logistics.php`; Эрээн хүлээн авалт, хэмжилт, зураг, багц, УБ тавиур, эцсийн төлбөр, хүлээлгэн өгөх. |
| Удирдлага | `/admin/`, `/warehouse/`; тусдаа эрх, захиалга ба агуулахын удирдлага. |

Худалдан авалтын дараалал: **каталог → SKU/тоо → серверийн үнийн санал → QPay баталгаажилт → TaoWorld дараалал → төсөв/үлдэгдлийн шалгалт → нийлүүлэгчийн захиалга ба төлбөрийн тулгалт → tracking → Эрээн → УБ → эцсийн тооцоо → хүлээлгэн өгөх**. QPay төлөгдсөн төлөв болон нийлүүлэгчид төлсөн төлөв тусдаа.

## Илэрсэн, зассан зүйлс

1. **Каталог унтраах тохиргоо native урсгалд бүрэн үйлчлэхгүй байсан.** Одоо TaoWorld хайлт, дэлгэрэнгүй, зурагт хайлт кэштэй байсан ч унтраасан үед 503 буцаана. Тусдаа procurement worker-ийн төлөвийн тулгалтыг энэ тохиргоо зогсоохгүй.
2. **Native API шинэ хүсэлтэд IP хязгаар дутуу байсан.** Одоо нийлүүлэгч рүү гарах хүсэлтэд минутын 30, цагийн 120 хязгаар болон өдрийн төсөв хамт үйлчилнэ. Кэшээс уншихад нийлүүлэгчийн квот/IP тоолуур зарцуулахгүй. Зэрэгцээ хайлтын төсвийн атомик нөөцлөлт хадгалагдсан.
3. **Админд хуучин OT кэш, cron, холболтын тайлбар харагдаж байсан.** TaoWorld горимд native кэшийн хугацаа, зөв provider, QPay → TaoWorld ажиллагаа харагдана. Хуучин OT данс холбох карт энэ горимд харагдахгүй. OT сонгосон үеийн удирдлага хэвээр.

Мөн навигацийн тестийн хуучирсан 10 брэнд/хэвтээ жагсаалтын хүлээлтийг одоогийн 12 брэндийн responsive grid-д нийцүүлэв. Загварыг тестэд тааруулж өөрчлөөгүй. README-ийн идэвхтэй provider, bundle, автомат худалдан авалтын тайлбарыг шинэчилсэн.

## Шалгалтын хамрах хүрээ

Эцсийн `tests/run-all.cjs` ажиллуулалт exit 0: **бүх бүртгэлтэй suite болон source syntax шалгалт тэнцсэн**. Эхний ажиллуулалтад зөвхөн хуучирсан навигацийн тест унасан; түүнийг шинэчилсний дараа бүх багцыг дахин ажиллуулсан.

- PHP/JavaScript 153 файлын syntax, frontend bundle-ийн нийцэл.
- Native auth, HMAC, token rotation, replay/account binding; каталогийн зэрэгцээ хайлт, үнэ yuan/fen, SKU/үлдэгдэл, кэш, хязгаар, хориотой бараа, зурагт хайлт.
- QPay нэхэмжлэл, хэсэгчилсэн/бүтэн төлбөр, давхар callback, timeout, захиалгын эзэмшигч, CSRF, давхар хүсэлт, зэрэгцээ өөрчлөлт.
- TaoWorld худалдан авалтын дараалал, төсөв давсан зогсолт, тогтвортой гадаад дугаар, crash/timeout тулгалт, нэг удаагийн төлбөр илгээлт, tracking давхардал, цуцлалт.
- Бүртгэл, нэвтрэлт, сагс, SKU, checkout, хадгалсан бараа, cross-device синк, хаяг, захиалгын түүх, хайлт, ангилал, тусламж.
- Админы CRUD, эрх, нууц үг шинэчлэлт; агуулахын салбар, хүлээн авалт, зураг, жин/хэмжээ, багц, QR/шошго, эцсийн төлбөр, нэг удаагийн авах код.
- 320–1440 px дэлгэцийн layout аудит: overflow болон JavaScript алдаа илрээгүй.
- Шинэ native browser fixture: 50 англи нэртэй бараа → зурагт хайлтын үр дүн → яг сонгосон SKU/тоо → серверийн дүн → native захиалга, мөн шинэ админ health UI. Бодит нийлүүлэгчийн сүлжээ, QPay энэ тестэд хаалттай.

Дахин ажиллуулах: `node tests/run-all.cjs` (локал tooling суусан орчинд). Түр өгөгдөл болон дэлгэцийн зургууд `tmp/`-д, Git-д орохгүй.

## Production дээр баталгаажуулсан

- Нүүр, сагс, тусламж, бүртгэл, захиалга, брэнд, бараа, админ, агуулахын 9 маршрут HTTP 200; холбогдох 36 статик asset HTTP 200. Энэ нь маршрут/файлын шалгалт; authenticated write урсгалын орлуулга биш.
- Засварын дараах public API шалгалтаар 50 барааны хайлт болон сонгосон барааны нэр/SKU бүхий дэлгэрэнгүй HTTP 200. Нэг удаагийн хэмжилт: хайлт 291 ms, дэлгэрэнгүй 2,545 ms; энэ нь тогтмол хурдын баталгаа биш.
- Нэвтрээгүй `dashboard`, `warehouse-orders`, TaoWorld connect GET хүсэлт HTTP 401.
- Серверийн тохиргоо, `.git`, `.vscode`, worker скрипт, `tmp`, лог, түлхүүрийн файлын зам HTTP 403. HTTP → HTTPS 308.
- SQLite `quick_check=ok`, foreign-key алдаа 0, захиалгын JSON алдаа 0; нийт 4 захиалга, төлөгдсөн 1, native `supplier_paid` 1.
- Native каталог, англи нэр, зурагт хайлт идэвхтэй; QPay production тохиргоотой; TaoWorld access/refresh token хугацаандаа.
- Автомат үүсгэлт болон төлбөр идэвхтэй. Worker-ийн 13:36:01 (Улаанбаатар) heartbeat аудитын үед 91 секундын өмнөх байсан.
- Дөрвөн байршуулсан файлын SHA-256 локалтай таарсан. Өмнөх хувилбар: `/gostore-backups/site-audit-20261030-faee952a7c`. Түр хамгаалагдсан шалгалтын endpoint-ийг устгасан.

## Үлдсэн хязгаар, анхаарах ажиллагаа

- Бодит туршилтын захиалга нийлүүлэгчид төлөгдсөн. Илгээмжийн tracking, биет Эрээн/УБ хүлээн авалт хараахан дуусаагүй; тэдгээрийг энэ аудит бодитоор баталсан гэж үзэхгүй.
- Үндсэн захиалгын төсвөөс Хятад доторх хүргэлт/үнэ нэмэгдвэл автомат худалдан авалт `preflight_review` дээр зогсоно. Админ дүнг шалгаж шийдвэрлэнэ.
- Эхний кэшгүй хайлт/дэлгэрэнгүй нь TaoWorld-ийн хариулах хугацаанаас хамаарна. Хурдын хэмжилт [performance-cache.md](performance-cache.md)-д бий.
- URL-ийн дотоод identity нь upstream-ийн одоогоор буцааж буй `item_id`-д тулгуурладаг; API хүсэлтэд `mi_id` ашиглана. Upstream хариунаас `item_id` хасагдвал identity migration шаардлагатай. Хуучин OT барааг native mapping үүсгэхийн тулд дахин хайна.
- Production дээр шинэ бодит төлбөр болон худалдан авалтыг давтаж хийгээгүй. Тестийн хуурамч нийлүүлэгчтэй амжилт нь ирээдүйн provider доголдол, бүх SKU, бүх банкны гүйлгээг баталгаажуулахгүй.
