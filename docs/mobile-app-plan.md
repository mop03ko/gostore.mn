# GOStore мобайл апп — судалгаа ба төлөвлөгөө (2026-10-26)

**Зөвлөмж:** Эхлээд одоогийн сайтыг 1–2 долоо хоногт PWA болгоно (суулгадаг, home screen icon, offline shell). Үүнтэй зэрэг PHP API-д мобайл токен нэвтрэлт, push мэдэгдэл нэмнэ. Дараа нь **Expo (React Native)** дээр хэрэглэгчийн native апп хийж, iOS/Android дээр нэг кодоор гаргана. Агуулахын (Эрээн/УБ) панелийг вэб/PWA хэлбэрээр нь үлдээнэ. Нэг хөгжүүлэгч бүтэн цагаар ажиллавал MVP-г store-д гаргах хүртэл ойролцоогоор 10–12 долоо хоног шаардлагатай. Энэ нь Store-ын хяналт болон шийдэгдээгүй асуултуудаас хамаарах таамаг юм.

Энэ бол төлөвлөгөө. Апп, store бүртгэл, push тохиргоо хараахан үүсээгүй. Судалгаанд repository-ийн `1565e63` хувилбар, live https://gostore.mn нүүр хуудас болон доорх эх сурвалжуудыг ашигласан.

## Нийлүүлэгчийн төлөв (2026-10-26, эзэмшигчийн мэдээлснээр)

- **OT Commerce:** API үйлчилгээ идэвхтэй. Апп каталогоо (хайлт, бараа, брэнд дэлгүүр) одоогийн OT адаптераас серверийн кэшээр авна. Захиалсан багцын өдрийн дуудлагын лимит кодын 800/өдөр тохиргоотой таарч байгаа эсэхийг шалгах хэрэгтэй (§5.8).
- **TaoWorld:** бүртгэл бэлэн, Alipay холбогдсон. Ингэснээр [TaoWorld төлөвлөгөө](taoworld-integration-plan.md)-ний нийлүүлэгчид төлбөр хийх сувгийн асуулт шийдэгдсэн. Нийлүүлэгчийн төлбөр нь хэрэглэгчийн QPay төлбөрөөс тусдаа (Alipay данс) хэвээр. Хөгжүүлэгчийн app (AppKey/AppSecret), API эрх, API-аар Alipay төлбөр хийх (`/purchase/order/batch/pay`) эрх нээгдсэн эсэх баталгаажаагүй байна.
- Аппын MVP нийлүүлэгчээс хамаарахгүй: худалдан авалт сервер/админ талд явагддаг тул OT-оос TaoWorld руу шилжихэд аппын код өөрчлөгдөхгүй.

## 1. Одоогийн байдал

### Бизнес загвар

- Монгол хэлтэй дэлгүүр. Taobao/1688-ын барааг OT Commerce API-аар хайж, ₮ үнээр харуулна. 12 брэндийн албан ёсны дэлгүүрийн хуудастай: Nike, adidas, Puma, New Balance, UNIQLO, ZARA, H&M, The North Face, Sony, Xiaomi, LEGO, IKEA ([supplier-brands.php](../server/supplier-brands.php)).
- Төлбөрийг хоёр шатаар авна. Эхлээд QPay-ээр бараа, Хятад доторх хүргэлт, үйлчилгээний төлбөрийг төлнө. УБ-д ирэхэд бодит жингээр каргоны эцсийн тооцоог гаргана ([freight-payment.php](../server/freight-payment.php)).
- Ачааны зам: Эрээн агуулах → Замын-Үүд → УБ агуулах → очиж авах/хүргэлт. Хэрэглэгч ачааныхаа явц, агуулахад ирсэн зургийг харна.
- Taobao-д захиалах ажлыг админ хийдэг. Автомат худалдан авалт анхдагчаар унтраалттай. Шууд TaoWorld холболтын төлөвлөгөө [taoworld-integration-plan.md](taoworld-integration-plan.md)-д бий.

## 2. Зах зээл ба өрсөлдөөн

- **Taobao Монголд албан ёсоор орсон** (ikon.mn, 2025-10-15). Эрээний хаяг, зуучлагчгүйгээр гэрийн хаяг руу 7–10 хоногт хүргэнэ. Монгол Шуудан, Hicargo хамтрагч. 49,999₮-өөс дээш захиалгыг үнэгүй хүргэнэ. Төлбөрийг VISA/Mastercard/Apple Pay/Google Pay/WeChat Pay-ээр авна. Интерфейс англи/орос/хятад хэлтэй, монгол хэлийг "AI-аар нэмэхээр төлөвлөж байна" гэсэн. [ikon.mn](https://ikon.mn/n/3iix)
- **Hibox** нь Бээжин, Эрээнд агуулахтай карго апп. Taobao/Tmall/1688-ын захиалгыг нэгтгэдэг. Ижил компанийн **HiCargo** апп нь АНУ → УБ чиглэлд төвлөрсөн. [Hibox](https://mwm.ai/apps/hibox-mn/1573876641), [HiCargo](https://mwm.ai/apps/hicargo/6741785585)
- **Eenoo** зэрэг хямд зуучлагчид хэрэглэгчийг Taobao-д өөрөө төлбөр хийлгэж, Эрээнээр дамжуулдаг. Энэ мэдээлэл хэрэглэгчийн бичсэн, хуучирсан байж болзошгүй Reddit wiki-д үндэслэсэн. [Reddit wiki](https://reddit.birdcat.cafe/r/Mongolia/wiki/logistics/cheap_shipping_guide)
- **Ozon** Монголын зах зээлд орж буй тухай мэдээ гарсан (10 хоногт УБ-д хүргэх). [oborot.ru](https://oborot.ru/news/za-10-dnej-do-ulan-batora-bez-sobstvennyh-pvz-i-skladov-kak-ozon-vyhodit-na-rynok-mongolii-i277859)

**Дүгнэлт.** Taobao өөрөө шууд үйлчилж эхэлснээр "Taobao-оос захиалах боломж" дангаараа давуу тал байхаа больсон. GOStore-ын аппын давуу тал нь:

1. **Бүрэн монгол хэл.** Бараа хайх, хувилбар сонгох, тусламж авах бүх алхам монгол хэлээр явна.
2. **QPay ба банкны апп.** Карт шаардахгүй. Монголд картаар гадаад худалдан авалт хийдэггүй хүмүүст хамгийн чухал саад.
3. **Ил тод ачаа.** Эрээн/УБ агуулахын зураг, явц, авах код. Push мэдэгдэл үүнийг утсан дээр шууд хүргэнэ.
4. **Шалгасан брэнд дэлгүүр.** Хуурамч бараанаас санаа зовдог хэрэглэгчид зориулсан албан ёсны 12 дэлгүүр.
5. **Хүний дэмжлэг.** Буруу хувилбар, гэмтэл, буцаалтыг агуулахын тулгалтаар шийддэг (`warehouse_exceptions`).

Аппын мессеж, App Store-ын тайлбар энэ таван зүйл дээр төвлөрнө. Үнийн өрсөлдөөнийг (Taobao-гийн үнэгүй хүргэлт) хүлээн зөвшөөрч, каргоны тооцоог урьдчилж ойлгомжтой харуулна.

## 4. Технологийн сонголт

**Сонголт: Expo (React Native + TypeScript), EAS Build/Submit, Expo Push.**

- iOS болон Android-ийг нэг кодоор гаргана. Push, SecureStore, камер, deeplink, OTA шинэчлэлтийг (EAS Update) бэлэн сангаар шийднэ.
- Backend-ийг өөрчлөхгүй. Апп нь одоогийн PHP API-ийн өөр нэг client болно.
- Expo Push service нь FCM/APNs-ийг нэг HTTP endpoint-оор нэгтгэдэг тул cPanel дээрх PHP-ээс `curl`-аар илгээхэд хангалттай.

Сонгоогүй хувилбарууд:

- **Зөвхөн PWA.** Эхний шатанд хийнэ. Гэхдээ iOS дээр push-ийг зөвхөн home screen-д суулгасан үед хүлээн авдаг, store-д харагддаггүй.
- **Capacitor-оор сайтыг ороох.** Хамгийн хурдан арга. Гэхдээ Apple "вэб сайтын хуулбар" гэж татгалзах эрсдэлтэй (Guideline 4.2), cookie session-ий асуудал хэвээр үлдэнэ.
- **Flutter.** Чанарын хувьд Expo-той ижил. Одоогийн код JavaScript дээр бичигдсэн тул TypeScript-т шилжих нь багт илүү хялбар.

## 5. Backend өөрчлөлт (апп эхлэхээс өмнө)

Эдгээр нь вэб сайтыг сайжруулах ажил ч мөн. Бүгдийг одоогийн PHP/SQLite дээр нэмэх хэлбэрээр (additive) хийж, вэбийн урсгалыг эвдэхгүй.

1. **Device token нэвтрэлт.**
   - `customer_devices` хүснэгт: `id`, `customer_id`, `token_hash` (SHA-256), `platform`, `push_token`, `app_version`, `created`, `last_seen`, `revoked_at`.
   - `customer-login` дээр `client=app` гэж ирвэл 32 байт санамсаргүй токен нэг удаа буцаана. Апп үүнийг `Authorization: Bearer` header-ээр илгээнэ. Bearer хүсэлтэд CSRF шаардахгүй, cookie ашиглахгүй.
   - Токен 90 хоног хүчинтэй, ашиглах бүрт сунгана. Нууц үг солих эсвэл `auth_version` өөрчлөгдөхөд бүх токен хүчингүй болно. Гарах үйлдэл тухайн токеныг цуцална.
   - Нэвтрэх оролдлогын лимит (`limit_attempts`) хэвээр үйлчилнэ.
2. **API гэрээ.** `api/index.php` дээр `X-Client: gostore-app/<version>` header, хариунд машинд уншигдах `code` талбар (`auth_required`, `price_changed`, `out_of_stock`, `rate_limited`...) нэмнэ. Монгол `error` мессеж хэвээр үлдэнэ. Аппын ашиглах action бүрийн хүсэлт/хариуг `docs/api-app.md` (эсвэл OpenAPI)-д бичнэ. `min_app_version` тохиргоогоор хуучин аппыг "шинэчилнэ үү" дэлгэц рүү шилжүүлнэ.
3. **Push мэдэгдэл.** `order_notifications`-д шинэ мөр нэмэгдэх бүрт тухайн хэрэглэгчийн идэвхтэй төхөөрөмжүүд рүү Expo Push илгээнэ. Илгээлтийн дараалал (`push_outbox`) ашиглаж, хүсэлтийн хариуг блоклохгүй. Expo-ийн receipt-ээр `DeviceNotRegistered` гэсэн токеныг устгана. **Анхааруулга:** cPanel cron-ийн ажиллагаа одоог хүртэл баталгаажаагүй ([performance-cache.md](performance-cache.md)). Push-ийн дарааллыг cron ажиллуулах уу, эсвэл хүсэлтийн дараа (`fastcgi_finish_request`) илгээх үү гэдгийг эхлээд шийднэ.
4. **Нууц үг сэргээх.** Нэг удаагийн, 30 минут хүчинтэй кодыг имэйлээр илгээнэ. Үүнд SMTP эсвэл имэйл үйлчилгээ (shop@gostore.mn домэйн, SPF/DKIM тохиргоотой) хэрэгтэй. Одоо сервер имэйл огт илгээдэггүй.
5. **Бүртгэл устгах.** Апп болон вэбээс бүртгэлээ устгах үйлдэл. Хувийн мэдээллийг (нэр, утас, хаяг, имэйл) устгаж эсвэл нэргүй болгоно. Санхүү/захиалгын бүртгэлийг хууль ёсны хугацаанд хадгална. Store-ын бүртгэлд вэб дээр устгах хүсэлт гаргах холбоос мөн шаардлагатай.
6. **Сагс ба хадгалсан барааны синк** (2-р шат). `customer_cart`, `customer_saved` хүснэгт нэмж, нэвтрэх үед localStorage-ийн өгөгдлийг нэгтгэнэ.
7. **Deeplink файлууд.** `/.well-known/apple-app-site-association` болон `/.well-known/assetlinks.json` файлыг нэмж, `.htaccess`-д JSON хэлбэрээр, redirect-гүйгээр үйлчилнэ.
8. **OT лимит хамгаалалт.** Аппын хайлт/жагсаалтыг вэбтэй ижил серверийн кэш, prefetch хязгаарлалтаар дамжуулна. Аппыг гаргахаас өмнө өдрийн 800 дуудлагын лимитийг дахин тооцоолж, шаардлагатай бол OT-оос лимит нэмүүлнэ.

| Ачаа | Захиалгын табууд (Төлбөр хүлээж буй / Замд / Авах / Хүлээн авсан / Цуцлагдсан), явцын timeline, агуулахын зураг, эцсийн нэхэмжлэл, авах код | `customer-orders`, `order-get`, `order-photo`, `freight-invoice` |
| Мэдэгдэл | Жагсаалт, уншсан гэж тэмдэглэх, push зөвшөөрлийн тохиргоо | `customer-notifications(-read)` |
| Би | Профайл, хаягууд, нууц үг, тусламж, нууцлалын бодлого, бүртгэл устгах, гарах | `customer-*` |

MVP-д оруулахгүй: харьцуулалт, 1688 үйлдвэрийн захиалга, бэлэн барааны дэлгүүр, агуулахын менежерийн функц, админ.

UX-ийн шаардлага:

- Бүх дэлгэцийн текст монгол хэлтэй. [Брэндийн гарын авлага](../GOStore-Brand-Guidelines-Detailed.pdf)-ийн өнгө (`#132344`) болон фонтыг ашиглана.
- Хайх, бараа үзэх дэлгэцийг нэвтрэхгүйгээр ашиглана. Checkout-ийн өмнө нэвтрүүлнэ (вэбийн guest-continuation урсгалтай ижил).
- Каргоны төлбөрийг хоёр дахь шатанд авдаг гэдгийг бараа, сагс, төлбөрийн дэлгэц бүр дээр тодорхой бичнэ. Хэрэглэгчийн гомдлын хамгийн их эх үүсвэр болох эрсдэлтэй.
- Push зөвшөөрлийг эхний захиалга төлсний дараа "Ачааныхаа явцыг мэдэгдлээр авах уу?" гэж асууна. Апп нээгдэхэд шууд асуухгүй.
- Хурд: зургийг CDN хэмжээгээр (thumbnail) авч, жагсаалтыг виртуалчилна. Сүлжээ удаан үед prefetch хийхгүй.

## 9. Хэмжүүр

GA4-ийн event нэршлийг вэб болон аппад ижил ашиглана (`view_item`, `add_to_cart`, `begin_checkout`, `purchase`, нэмээд `freight_paid`, `pickup_completed`).

- Суулгалт → бүртгэл → эхний төлсөн захиалга хүртэлх хувь
- Checkout → QPay төлбөр төлөгдсөн хувь (вэб болон апп-ыг харьцуулна. Банкны deeplink-ийн нөлөөг хэмжинэ)
- Эцсийн нэхэмжлэл гарснаас төлөгдөх хүртэлх дундаж хугацаа (push-ийн нөлөө)
- Push зөвшөөрсөн хувь, мэдэгдэл нээсэн хувь
- 60 хоногийн дотор дахин захиалсан хэрэглэгчийн хувь
- Crash-free session, API алдааны хувь, OT лимитийн өдрийн хэрэглээ

## 11. Шийдвэр хүлээж буй асуултууд

1. Аппыг ямар хуулийн этгээдийн нэрээр бүртгүүлэх вэ? D-U-N-S дугаар бий юу?
2. Аппыг өөрсдөө хөгжүүлэх үү, гэрээт баг авах уу? Дизайныг хэн хийх вэ?
3. Имэйл илгээх үйлчилгээ: cPanel SMTP уу, гадны үйлчилгээ үү? SMS-ээр баталгаажуулах шаардлагатай юу?
4. Google/Facebook нэвтрэлтийг MVP-д нэмэх үү? Нэмбэл Sign in with Apple мөн шаардлагатай болно.
5. Аппыг зөвхөн апп-д зориулсан хямдралаар сурталчлах уу (жишээ нь эхний захиалгын үйлчилгээний хураамжийг хөнгөлөх)?
6. Аппыг монорепо хэлбэрээр энэ repository-ийн `app/` хавтаст байршуулах уу, тусдаа repository үүсгэх үү? Зөвлөмж: API гэрээ болон тест нэг дор байх үүднээс `app/` хавтаст байршуулах.
