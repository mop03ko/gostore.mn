# Эрээнээс Улаанбаатар хүрэх тээврийн тооцоо

Эрээн менежер барааг зурагтай хүлээн авч, төлөвийг `erenhot` болгосны дараа
**二连 → 乌兰巴托 · 运费** хэсэгт тооцоо хийнэ.

1. **按重量** — захиалгын нийт кг; эсвэл **按体积** — савласан нийт хэмжээ.
   Эзлэхүүнийг урт × өргөн × өндөр (см), эсвэл шууд м³-ээр оруулж болно.
2. Бүх барааны тоог тулгаад **计算运费** дарна. Тоо ширхэгээр тээврийн үнийг
   дахин үржүүлэхгүй. Сонгоогүй аргын хэмжилтийг заавал шаардахгүй.
3. Серверийн тооцсон дүн, арга, тарифыг шалгаж checkbox сонгоод
   **确认运费** дарна. Ажилтны баталгаа audit-д бүртгэгдэнэ.
4. Хэмжилтийг дахин оруулбал өмнөх баталгаа хүчингүй болж дахин батална.

Тариф нь захиалгад хадгалсан `quote.rates`, байхгүй бол админы одоогийн
каргоны тариф. Жинг тарифын алхмаар дээш бүхэлчилнэ. Эзлэхүүний босгоос
бага үед жижиг, босготой тэнцүү/их үед том ачааны CNY/m³ тариф ашиглан,
хадгалсан CNY→MNT ханшаар хөрвүүлнэ. Эцсийн дүнг төгрөгөөр дээш бүхэлчилнэ.

Тооцоо `logistics.transport` дотор арга, хэмжилт, хэмжээ, тоо, тариф,
ханш, дүн, хугацаа, агуулахын хамт хадгалагдана. Баталгаажуулалт нь
`expected_version`, `expected_amount_mnt`, `checked` шаарддаг; дүнг
browser-оос дур мэдэн солихгүй. Батлахаас өмнө нээлттэй зөрчил шийдэгдсэн байна.

Шинэ тооцоо үүссэн бол баталгаажаагүй үед багцыг бэлэн болгох/илгээхгүй.
Өмнөх хувилбарын зөвхөн хэмжилттэй ачаанд хуучин урсгал үйлчилнэ; шинэ
хэмжилт/дахин тооцоо бүр батлах шаардлагатай дүн үүсгэнэ. Багцалсан барааны
тооцоог засахын өмнө багцыг буцаан нээх шаардлагатай.

УБ агуулахын эцсийн тооцоо баталсан тээврийн дүнг нэг удаа нэмж ашиглана.
Тариф дараа нь өөрчлөгдсөн ч баталсан дүн өөрчлөгдөхгүй. УБ менежер энэ
тээврийн аргыг солихгүй; бараа, Хятад хүргэлт болон УБ хүргэлтийн бусад
зардлыг өмнөх урсгалаар тулгана. Энэ баталгаа QPay төлбөр үүсгэхгүй.

Шалгалт: `tests/warehouse-cargo.mjs`, `tests/warehouse-cargo-ui.cjs` болон
агуулахын batch/branch/logistics API, UI тестүүд. Жингийн шатлал, эзлэхүүний
босго, шууд м³, баталгаа, хуучирсан хувилбар, шинэ хэмжилт, УБ тооцоо шалгагдана.
